## При компрессии контекста сохранить

- Текущую задачу и её статус (из `tasks/todo.md`)
- Архитектурные решения принятые в этой сессии
- Пути файлов с которыми работаем прямо сейчас
- Незакрытые вопросы к пользователю
- Ограничения среды (что не работает и почему)

---

## Правила краткости

- Без вступлений: не писать "Sure!", "Of course!", "Отличный вопрос!" и подобное
- Без повторения задачи перед ответом
- Без итогов и резюме в конце если не просят
- Без извинений и самооценки
- Код без объясняющих комментариев если логика очевидна
- Если нужно уточнение — один вопрос, не список
- Одно предложение вместо абзаца там где достаточно

## Рабочий процесс

1. Claude пишет код → пушит в ветку `claude/...`
2. Открывает PR в `main` (не draft — иначе automerge не сработает без ручного ready_for_review)
3. `automerge.yml` мержит squash'ем
4. Никогда не мержить в `main` вручную без явного подтверждения
5. Никогда не использовать `--no-verify`, `--force`, `--no-gpg-sign`

---

## Правила редактирования файлов

- Через GitHub MCP: `create_or_update_file` для одиночных, `push_files` для батчей
- Перед обновлением существующего файла — получить `sha` через `get_file_contents`
- Для миграций Supabase — отдельный файл на каждую миграцию, никогда не править прошлые

## Начало и конец сессии

**Начало (ОБЯЗАТЕЛЬНО):**
1. **Прочитать `tasks/SESSION_LOG.md` первым** — верхняя запись = точка возобновления.
2. Прочитать `SYSTEM.md`, `CLAUDE.md`, `docs/PLAN.md`, `tasks/todo.md`.
3. Если в SESSION_LOG есть «незакрытые вопросы» или «следующие шаги» — предложить продолжить с них или взять новое.
4. Не переспрашивать пользователя то что уже есть в SESSION_LOG.

**Конец** (триггеры: "закрываем сессию", "на сегодня хватит", "продолжим завтра", "я ухожу", «перерыв»):
1. **Дописать новую секцию сверху в `tasks/SESSION_LOG.md`** — формат см. SYSTEM.md §8.
2. Обновить `tasks/todo.md`: предыдущую `[актуально]` → `[устарело]`, новую сверху.
3. Закоммитить и запушить (отдельным PR «docs: session log YYYY-MM-DD»).
4. Только потом попрощаться.
