### Задача: автосбор годового отчёта поисковых запросов через официальный API

Отчёт «Поисковые запросы по вашим товарам» владелица выгружает вручную в xlsx
и присылает zip'ом. Он лежит в основе всей пересборки наименований: за 28.08
по нему переписаны четыре группы. Забирать его можно официальным API — тем же,
за который уже платится подписка «Джем».

Метод: `POST /api/v2/search-report/report`, хост `seller-analytics-api.wildberries.ru`,
раздел аналитики продавца, доступен только с подпиской «Джем». Отдаёт **только наши
номенклатуры** — чужую полку официальный API не отдаёт вообще, второй срез
остаётся за платным сервисом (см. решение по Эвирме ниже).

Сделать:
1. **Разведка контракта** через `probe-wb-api` — точная форма запроса и ответа
   неизвестна: `dev.wildberries.ru` заблокирован egress-прокси, писать маппинг
   по памяти нельзя. Сырой ответ ложится в `ingestion_log.meta.probe`.
2. Функция `fetch-wb-search-queries` по образцу `fetch-wb-funnel`: `checkCronSecret`,
   `WB_TOKEN_READ`, запись в `ingestion_log`, upsert в `wb_search_queries`
   по ключу `(period_from, period_to, nm_id, query)`.
3. Крон — раз в месяц. Каждый прогон = новый период, старые остаются:
   на этом стоит `v_search_query_delta` и весь замер (`docs/seo/measurement.md`).

Оценка: два часа, из них час на разведку контракта.
**Остановлено владелицей 28.08 на шаге 1 — «пока стоп, не торопимся».**
Возобновлять по явному слову.

## 🔮 Перспектива (по концепции «всё в проге, никаких импортов»)

> Принцип: константы и заказы вводятся **в проге при каждой поставке**, прога считает поставки и **генерирует** ТЗ-ФФ. Долгосрочно WB-токен с правом записи → автопуш поставок в WB + ФФ.

- [ ] **История констант** — при каждом вводе курса юаня/доллара/доставки/себеса записывать снапшот (`tariff_constants_history`). - [ ] **COGS по FIFO из sku_cost_history** — каждая запись `cost` с датой = отдельная «партия» товара. При продаже списываем по методу FIFO (первый пришёл первый ушёл, как в 1С у владелицы). - [ ] **Калькулятор поставки** — UI на основе `v_supply_recommendation`: прога считает qty per склад по продажам / остаткам / lead_time / safety_stock. Кнопка «Создать поставку» → попадает в `wb_supplies_planned`.
