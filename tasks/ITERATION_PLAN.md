## 🔮 Backlog для отдельных задач

### fetch-wb-orders (новый Edge Function)
Нужен для вкладки «Заказы» в WB-style графике дашборда.
- Источник: WB Statistics API `/api/v1/supplier/orders` (или новый аналог)
- Поля: orderId, date (с минутной точностью), nmId, totalPrice, srid, finishedPrice, cancelDt, ...
- Таблица: `wb_orders_fact` (по аналогии с `wb_sales_fact`)
- Cron: каждые 30 минут как `fetch-wb-sales-30min`
- Отличие от продаж: заказ создаётся при оформлении (может быть отменён); продажа = выкуп.

### fetch-wb-ads (новый Edge Function)
Нужен для вкладки «Продвижение» в WB-style графике дашборда.
- Источник: WB Promotion API `/adv/v1/...` (рекламные кампании, расходы)
- Поля: campaignId, date, sumSpent, views, clicks, ctr, orders, ...
- Таблица: `wb_ads_fact`
- Cron: ежедневно
- Использование: Маркетинг как статья расходов в P&L (сейчас 0).

### WB-style график дашборда (текущая итерация частично)
Делается сейчас: вкладки **Выкупы** + **Приход и расход** работают на текущих данных.
Вкладки «Заказы» и «Продвижение» = заглушки «скоро — нужен fetch-wb-orders / fetch-wb-ads».
После реализации backlog-функций заглушки активируем.
