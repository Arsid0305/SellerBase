## Контекст

Цель: заменить Excel-комплекс (UNIT, ПОСТАВКА, CF/PL) единой data-платформой
для управления бизнесом на маркетплейсах. MVP — Wildberries.

**Стек по факту:**

- Фронт: Next.js 15 / React 19, feature-sliced (`apps/web`), деплой на Vercel
- Бэк: Supabase — PostgreSQL, Edge Functions, `pg_cron` + `pg_net`, Vault
- Пакеты: pnpm, монорепо
- Бот: `telegram-webhook` + `telegram-alerts`

## Принципы надёжности и расширяемости

Не менялись, остаются фундаментом. Проверка на соблюдение — в `AUDIT_PROMPT.md`.

1. **Сырые данные отдельно от расчётных** (`raw` JSONB из API → нормализатор → `*_fact`).
2. **Idempotent UPSERT** по бизнес-ключу.
3. **`ingestion_log`** — здоровье системы.
4. **Расчёты — только VIEW**.
5. **Декомпозиция view** — маленькие → большие.
6. **`v_data_quality`** — sanity-checks.
7. **`app_settings`** — key/value для внутренних коэффициентов.
8. **История** у всего что меняется.
9. **Расширение через добавление**, не переписывание.
10. **Edge Functions ловят ошибки в `ingestion_log`**.

Соблюдаются не везде — расхождения зафиксированы в `AUDIT_2026-08-21_repo-vs-prod.md`.
Главное: `raw` есть у 7 таблиц `wb_*` из 23, `try_job_lock` не вызывает ни одна функция.

## Чего нет вовсе

Это не «недоделано» — этого нет в системе ни строкой.

**Ozon — ноль.** Ни одного обращения к API Ozon ни в функциях, ни в вебе.
Слово «ozon» встречается в 32 файлах фронта, но это фильтры, перечисления и
демо-данные. При этом каталог к Ozon готов: поле `ozon_article` заполнено
у 57 SKU из 80.

**FBS — ноль.** Все 24 склада в заказах — склады WB (FBO). Сборочных заданий
FBS нет ни в коде, ни в базе: они приходят другим методом API.

**Фулфилмент — ноль.** `external_stock` (остаток вне складов WB) пуст.
Три ставки расходов до отгрузки — `supplies_transport`, `fulfillment_costs`,
`delivery_to_wb` — пусты, поэтому колонка «Итого с ФФ» на странице
себестоимости равна обычной себестоимости.

**План поставок пуст.** `supply_plans`, `supply_plan_items`,
`supply_plan_china` — 0 строк. Страница «Поставки» описана как «планы закупок
из Китая + FBW-поставки с расчётом доставки на единицу», но планов в ней нет.

**Замер эффекта правок карточек невозможен.** `wb_card_uploads` пуст — не с чем
сравнивать воронку «до и после».

## Инфраструктура и ограничения

**Деплой Edge Functions.** GitHub Actions отключены с 11.07.2026 после срабатывания
anti-abuse (см. `llm_wiki/wiki/lessons.md`). Рабочий путь — MCP `deploy_edge_function`.
С 11.07 по 21.08 доехала одна функция из восьми изменённых; 21.08 выложены ещё две.

**Миграции.** Только через MCP `apply_migration`, CLI нет. Имя в
`supabase_migrations.schema_migrations` задаётся вручную и с именем файла не совпадает —
сверять состояние нужно по создаваемым объектам, а не по именам.

**Запуск функций вручную.** Из SQL, как это делает cron:

```sql
SELECT net.http_post(
  url := 'https://hcebwgjgppwaguqittpi.supabase.co/functions/v1/<имя>',
  headers := jsonb_build_object(
    'Content-Type','application/json',
    'Authorization','Bearer '||(SELECT decrypted_secret FROM vault.decrypted_secrets WHERE name='service_role_key'),
    'X-Cron-Secret',(SELECT decrypted_secret FROM vault.decrypted_secrets WHERE name='cron_shared_secret')),
  body := '{}'::jsonb,
  timeout_milliseconds := 180000);
```

Секреты берутся из Vault — знать их не нужно.

**Токен WB.** `WB_TOKEN_READ` в Supabase Secrets. Права у него шире чтения, но
**записи из системы больше нет**: 05.09.2026 по решению владелицы удалены обе
write-функции — `set-wb-price` и `create-wb-supply`. Цены и поставки заводятся
вручную в кабинете. Возврат — только по её прямому распоряжению, отдельным
write-токеном и с журналом операций; прежний код в истории git.

## Направления

Приоритеты и конкретные задачи — в `../tasks/todo.md`, там же обоснование порядка.

Порядок на 16.09.2026, от приоритета владелицы:

1. **Отгрузки** — её главное сейчас. Ведутся через кабинеты WB, Ozon и
   фулфилмент. Система может помочь двумя вещами: сколько и чего везти
   (дефицит и оборачиваемость считаются; расчёт «сколько заказать» на 16.09
   даёт 0 по всем SKU — запаса при нынешней скорости хватает надолго) и во
   сколько это обходится за единицу (нужны три ставки).
   Кода почти не требует: требует ввода и доделок поверх заложенного.
2. **Ozon — сбор данных.** Пока его нет, половина бизнеса невидима, и любой
   сводный отчёт слеп на эту половину.
3. **FBS** — когда кабинеты заработают. Отдельный метод API, отдельные
   сборочные задания.
4. **Недельный снимок бизнеса** — строить на том, что собрано. По WB большая
   часть достижима уже сегодня; по Ozon — ничего до пункта 2.

**Позже** — мультитенантность (`MULTI_TENANT_PLAN.md`).
