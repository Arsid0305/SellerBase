## 🔴 F1 · Две конкурирующие формулы cogs+tax между `get_pnl_by_period` и `get_daily_pnl_series`

**Where:**
- `get_pnl_by_period` (миграция `20260705170000_cost_at_and_pnl_fifo.sql:33`) — cogs через `cost_at(sku_id, rr_dt)` (FIFO), tax = `retail_amount × 0.06`.
- `get_daily_pnl_series` (миграция `20260614_daily_pnl_with_cogs.sql:52`) — cogs = `qty × sku_catalog.cost_price_rub` (current), tax = `revenue × app_setting_num('tax_rate')`.

**Факт:** на `/pnl` KPI-карточки сверху берут цифры из `get_pnl_by_period` (FIFO), а график динамики под ними из `get_daily_pnl_series` (current). Итог: сумма всех дней графика ≠ значение KPI.

**Прямое нарушение AUDIT_PROMPT §Данные:** «Нет двух конкурирующих версий формулы в проде».

## 🔴 F2 · Все новые edge functions без `pg_advisory_lock` — зомби-джобы возможны

**Where:** `create-wb-supply`, `set-wb-price`, `fetch-wb-feedback`, `fetch-wb-prices`, `fetch-wb-supplies`, `telegram-indices-reminder` — ни в одной нет lock.

**Факт:** если pg_cron дёрнет функцию дважды за счёт retry или ручной hit + cron совпадут — параллельные запуски. Для `fetch-wb-*` это дубли upsert (обойдётся, но зря WB-квота), для `create-wb-supply` — риск двойного POST в WB API.

**Прямое нарушение AUDIT_PROMPT §Edge Functions:** «`pg_advisory_lock` на входе каждой ingestion-функции».

## 🟡 F5 · Ни в одной новой edge function нет retry на WB 429/5xx

**Where:** `fetch-wb-prices`, `fetch-wb-feedback`, `fetch-wb-supplies`, `set-wb-price`, `create-wb-supply` — при `!resp.ok` бросают исключение и падают.

**Факт:** WB Prices API — 10 req/min, Feedback API — 1 req/sec, Supplies API — 100 req/min. При батчевой обработке (fetch-wb-supplies по каждой поставке GET goods в цикле) первое 429 = вся сессия провалена, partial state в БД (часть поставок upsert, часть — нет).

## 🟡 F8 · Weighted-average вместо строгого FIFO

**Where:** `apps/web/src/app/api/china-order/create/route.ts:106-120` и SQL импорт (в комментариях к PR #206)
```ts
bySku.set(skuId, { cost: (prev.cost * prev.qty + costPerUnit * qty) / totalQty, qty: totalQty });
```

**Факт:** если один SKU встречается в 3 строках одного заказа (например разные цвета одного nm_id), их себестоимости усредняются. Это НЕ FIFO, а weighted-avg. Владелица в 1С считает FIFO по партиям с qty (первый пришёл — первый ушёл).

Реальное расхождение с 1С за неделю 25 (15-21.06): моя cogs 11 332 vs Excel 15 866 — 40% ошибка, вероятно из-за этой причины.
