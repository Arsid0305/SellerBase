# ФБС на двух площадках - что отдают API

Точка входа по модели «Маркетплейс» (ФБС) на ВБ и Ozon. Проверено запросами
к живым API 17.09.2026: документация обеих площадок из рабочей среды закрыта
сетевым фильтром, поиск даёт только пересказы. Поэтому всё ниже - ответы
самих площадок, а не чтение документации.

Владелица начинает торговать по ФБС и там, и там, и делает отгрузки. После
них станет ясно, сколько останется на фулфилменте.

## Главная находка: склад продавца на ВБ уже есть

`GET /api/v3/warehouses` (marketplace-api.wildberries.ru) отвечает:

```
name: «Москва (Чашниково)», id: 2034886, officeId: 14993, storeId: 324107
```

Это и есть фулфилмент. То есть **остатки ФБС не надо заводить руками** -
площадки их знают, потому что она сама заявляет им доступное количество.
Ручная таблица `external_stock` для этого не нужна.

## Wildberries

Всё отвечает, токен доступ имеет.

| Что нужно | Метод | Ответ |
|---|---|---|
| Склады продавца | `GET /api/v3/warehouses` | 1 склад, «Москва (Чашниково)» |
| Остатки на складе продавца | `POST /api/v3/stocks/{warehouseId}` | 200, `stocks: []` - пока пусто |
| Сборочные задания ФБС | `GET /api/v3/orders` | 200, заданий пока нет |
| Новые задания | `GET /api/v3/orders/new` | 200, пусто |
| Поставки ФБС | `GET /api/v3/supplies` | 200, одна старая от 17.11.2023 |
| Продажи, все модели | `GET /api/v1/supplier/sales` | 200, 37 продаж за 7 дней |

**Как отличить ФБС от ФБО.** В продажах есть поле `warehouseType`. Сейчас у
всех строк `«Склад WB»` - это ФБО. У продаж со склада продавца значение
будет другим. Это и есть признак, по которому продажи делятся на модели -
угадывать по имени склада не нужно.

Отдельно `warehouseName` = «Склад WB РФ» - тот самый единственный живой
склад ФБО.

## Ozon

| Что нужно | Метод | Ответ |
|---|---|---|
| Отправления ФБС | `POST /v3/posting/fbs/list` | 200, отправлений пока нет |
| Остатки, все модели | `POST /v4/product/info/stocks` | 200, работает |
| Остатки по складам ФБС | `POST /v2/product/info/stocks-by-warehouse/fbs` | метод живой, нужен `limit` |
| Склады ФБС | `POST /v1/warehouse/list` | ❌ погашен |
| Остатки ФБС v1 | `POST /v1/product/info/stocks-by-warehouse/fbs` | ❌ погашен |

**Как отличить ФБС от ФБО.** В `/v4/product/info/stocks` каждый товар
отдаётся со списком `stocks`, где у каждой записи есть `type`: `fbo` или
`fbs`, плюс `present`, `reserved` и `warehouse_ids`. Это уже собирается -
в `ozon_stocks` поле `stock_type`.

В отправлениях модель различается полем `scheme` - тоже уже собирается,
в `ozon_postings`.

Два метода погашены («obsolete method cannot be used»), и это не ошибка
запроса: тот же ответ Ozon даёт на метод транзакций. Живая замена для
разбивки по складам ФБС - `v2/product/info/stocks-by-warehouse/fbs`, он
ответил не «погашен», а «неверный limit», то есть работает.

## Подвох, который надо держать в голове

Фулфилмент - **один физический склад**, с него торгуется и ВБ, и Ozon.
А площадкам заявляется доступное количество отдельно.

Значит:

- **физический остаток на ФФ** знает только фулфилмент;
- **что заявлено на ВБ** - `GET /api/v3/stocks/{warehouseId}`;
- **что заявлено на Ozon** - `stocks` с `type: fbs`;
- **складывать заявленное нельзя** - это одна и та же куча, показанная
  двум площадкам. Сумма даст двойной счёт.

Поэтому в таблице по артикулам строки ФБС должны быть про заявленное по
каждой площадке, а физический остаток ФФ - отдельным столбцом, и он
приходит не от площадок.

## Оборачиваемость ФБС

Считается против суммы продаж обеих площадок по этой модели: товар лежит
одной кучей, и расходится она с двух сторон одновременно.

Где продаж не было - пишем «нет продаж», а не число. Правило владелицы
17.09.2026: «ничего выдумывать не надо, если не было продаж просто пишешь
не было продаж».

## Что из этого уже собирается

- остатки Ozon с разделением ФБО / ФБС - да, `ozon_stocks.stock_type`
- отправления Ozon с моделью - да, `ozon_postings.scheme`
- продажи ВБ - да, но **без признака модели**: в `wb_reports_fact` его нет,
  а `warehouseType` живёт в другом отчёте (`supplier/sales`)
- остатки на складе продавца ВБ - **нет, не собираются**
- сборочные задания ВБ - **нет, не собираются**

## Что осталось сделать

1. Забирать склады продавца и остатки на них с ВБ (`api/v3/warehouses`,
   `api/v3/stocks/{id}`).
2. Тянуть `supplier/sales` с полем `warehouseType` - иначе продажи ВБ по
   моделям не разделить.
3. Довести разбивку остатков Ozon по складам ФБС - `v2` с `limit`.
4. Физический остаток ФФ - источник пока не решён, это вопрос к владелице.
