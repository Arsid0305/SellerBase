# WB API — токены и интеграция

Подход: **один токен `WB_TOKEN` для SellerBase** со всеми нужными группами + **отдельный токен только для бота** с группой «Вопросы и отзывы».

---

## 1. Токен для SellerBase

### Группы, которые включить в WB-кабинете

Один токен покрывает всё веб-приложение:

- ✅ **Статистика** — отчёты продаж, остатки, реализация (уже используется на дашборде, P&L, каталоге, аномалиях, событиях)
- ✅ **Контент** — карточки товаров, фото, рейтинг, отзывы-счётчик
- ✅ **Цены и скидки** — менять цену из приложения
- ✅ **Продвижение** — данные рекламных кампаний (бюджет, CPC, ROAS)
- ✅ **Тарифы** — актуальные коэффициенты складов и логистики

Группы НЕ включать:
- ❌ Вопросы и отзывы → отдельный токен у бота
- ❌ FBS / Marketplace → у тебя FBO, не нужен
- ❌ Поставки → возьмёмся позже отдельным токеном

### Куда положить токен

**Имя переменной:** `WB_TOKEN`

**В Vercel** (для веб-приложения):
1. https://vercel.com → проект SellerBase
2. **Settings → Environment Variables**
3. **Add New** → Name: `WB_TOKEN`, Value: вставить токен
4. Environments: ✅ Production, ✅ Preview, ✅ Development
5. **Save**

**В Supabase** (для Edge Functions, которые читают WB):
1. https://supabase.com → проект `hcebwgjgppwaguqittpi`
2. **Edge Functions → Manage secrets**
3. **Add new secret** → Name: `WB_TOKEN`, Value: вставить
4. **Save**

### Что я подключу, когда токен появится

| Раздел | Что подключим | Время |
|---|---|---|
| Контент | Cron `fetch-wb-content` ежедневно: title/brand/category/rating/reviews_count в `sku_catalog` + `sku_snapshots` | 2-3 часа |
| Цены | Server action POST `/api/prices` + кнопка-карандаш у цены товара | 1-2 часа |
| Реклама | Edge Function `fetch-wb-adv` каждый час → таблицы кампаний, замена мока на `/ads` | 3-4 часа |
| Тарифы | Edge Function `fetch-wb-tariffs` ежедневно → актуальные коэффициенты на `/tariffs` | 2 часа |

Когда токен в env — пишешь «Добавила `WB_TOKEN`», я подключаю.

## 2. Токен для бота (ReviewBot)

### Группа

- ✅ **Вопросы и отзывы** (и только она)

### Куда положить

В директорию бота: файл `.env` рядом с `ReviewBot.bat`. Содержимое:

```
WB_FEEDBACKS_TOKEN=ваш_токен_здесь
```

Имя переменной в самом боте может отличаться — посмотри в его `connectors/wb_connector.py`. Если он берёт через `os.getenv('WB_FEEDBACKS_TOKEN')` — используй это имя. Если другое — переименуй.

### Что это даст

- Бот сам читает новые отзывы/вопросы из WB и пишет ответы
- (Опционально, позже) дублирование в Supabase-таблицу `review_replies` — SellerBase будет показывать статистику ответов в разделе «Отзывы»

## Шаги в WB-кабинете для каждого из 2 токенов

1. https://seller.wildberries.ru → **Профиль → Настройки → Доступ к API**
2. **Создать новый токен**
3. Имя для понимания:
   - Токен 1: `SellerBase Web`
   - Токен 2: `ReviewBot`
4. **Срок действия:** 1 год (макс)
5. **Тип токена:** Стандартный (НЕ «Только на чтение», если планируешь менять цены через SellerBase)
6. Выбрать группы из таблиц выше
7. **Сохранить** → скопировать токен (показывается один раз)
8. Положить туда где указано (Vercel/Supabase для SellerBase, `.env` для бота)

## После того как старый токен удалён

Если был старый токен с большим scope — после переноса всего на новый `WB_TOKEN`:

1. WB-кабинет → **Доступ к API** → найти старый → **Отозвать**
2. Проверить что у тебя нет других мест где он используется (старые скрипты, Excel-макросы и т.п.)

Если что-то отвалится — сразу видно в `/health` в SellerBase (страница покажет «нет свежих данных»).

---

## Меры безопасности

- Токен `WB_TOKEN` имеет права менять цены — компрометация = убыток. Хранить только в Vercel/Supabase env, никогда не в git, в чате, в скриншотах
- Токен бота слабее — только отзывы, риск ниже
- При утечке — сразу отозвать в WB-кабинете и создать новый, обновить env
- Срок 1 год → ставь напоминание в календаре за месяц до конца
- В коде SellerBase токен берётся только в server-side (Edge Functions, server actions), на клиент никогда не попадает
