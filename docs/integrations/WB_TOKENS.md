## Что добавляем (приоритет сверху вниз)

### 1. `WB_CONTENT_TOKEN` — Контент (приоритет 1)

**Что даёт:** реальные карточки товаров — название, бренд, категория, фото, рейтинг, отзывы. Без этого `sku_snapshots` пишут только то что есть в нашей таблице, а не источник истины.

**Куда подключим:**
- Edge Function `fetch-wb-content` (новая) — раз в день обновляет поля карточки в `sku_catalog` (title, brand, category, rating, reviews_count, photo_url)
- Cron 03:00 МСК
- Заодно `sku_snapshots` начнут содержать реальные rating и reviews_count, история отзывов оживёт

**Группы в WB-кабинете при создании:**
- ✅ Контент

---

### 2. `WB_PRICES_TOKEN` — Цены и скидки (приоритет 2)

**Что даёт:** менять цену/скидку прямо из SellerBase. На карточке товара появится кнопка «Изменить цену», в задаче — действие «применить новую цену».

**Куда подключим:**
- Server action `/api/prices` (POST) — принимает `{ barcode, newPrice, newDiscount }`, дёргает WB API
- На карточке товара — кнопка-карандаш у поля цены
- В разделе «Задачи» — тип задачи «Изменить цену» с авто-применением по дедлайну

**Группы в WB-кабинете:**
- ✅ Цены и скидки

---

### 3. `WB_ADV_TOKEN` — Реклама (приоритет 3)

**Что даёт:** реальные данные по рекламным кампаниям — бюджет, ставки, CPC, заказы, ROAS. Сейчас на `/ads` мок.

**Куда подключим:**
- Edge Function `fetch-wb-adv` — раз в час подтягивает статистику кампаний
- Таблицы `wb_adv_campaigns`, `wb_adv_stats` (миграция нужна)
- Страница `/ads` переключается с мока на реальные данные
- В аномалиях добавится тип «CPC вырос на N%»

**Группы в WB-кабинете:**
- ✅ Продвижение

---

### 4. `WB_FEEDBACKS_TOKEN` — Отзывы и вопросы (приоритет 4)

**Что даёт:** список новых отзывов/вопросов, отправка ответов. Связка с твоим ботом ReviewBot.

**Куда подключим:**
- Edge Function `fetch-wb-feedbacks` — раз в час тянет новые отзывы в таблицу `reviews`
- На странице `/reviews` будут реальные отзывы
- Бот пишет ответ → INSERT в `review_replies` → SellerBase видит ответ в архиве
- Метрика «среднее время ответа» появится автоматически

**Группы в WB-кабинете:**
- ✅ Вопросы и отзывы

**Важно:** этот же токен можно дать боту в его `.env` — будет читать тем же ключом, не нужно два.

---

### 5. `WB_TARIFFS_TOKEN` — Тарифы (приоритет 5)

**Что даёт:** актуальные коэффициенты складов, базовые ставки логистики, индексы. Сейчас на `/tariffs` цифры захардкожены — устаревают как только WB поменяет тариф.

**Куда подключим:**
- Edge Function `fetch-wb-tariffs` — раз в день
- Таблица `wb_tariffs` (миграция)
- `/tariffs` показывает актуальное на сегодня

**Группы в WB-кабинете:**
- ✅ Тарифы

---

## Как добавить в Vercel (пошагово)

### Шаг 1. В кабинете Wildberries

1. Открыть https://seller.wildberries.ru
2. Профиль → **Настройки** → **Доступ к API**
3. Кнопка **Создать новый токен**
4. Введи имя: например `SellerBase Content` (для понимания зачем)
5. Срок действия: 1 год (макс)
6. **Тип токена:** оставь **Стандартный** (НЕ Только на чтение, если нужно менять цены — но для контента/тарифов/отзывов «только чтение» подойдёт)
7. **Выбери группы** из таблицы выше для текущего токена
8. Сохрани → скопируй токен (показывается один раз!)

Повторить для каждого токена. **Никогда не вставляй токен в чат или в код напрямую.**

### Шаг 2. В Vercel

1. https://vercel.com → проект SellerBase
2. **Settings** → **Environment Variables**
3. Кнопка **Add New**
4. Поле `Name`: имя из таблицы выше (например `WB_CONTENT_TOKEN`)
5. Поле `Value`: вставить токен
6. Environments: выбрать **Production** + **Preview** + **Development**
7. **Save**

### Шаг 3. В Supabase (Edge Functions)

Edge Functions работают на стороне Supabase, не Vercel. Им нужны те же токены отдельно.

1. https://supabase.com → проект `hcebwgjgppwaguqittpi`
2. **Edge Functions** → **Manage secrets**
3. Кнопка **Add new secret**
4. Имя и значение — то же что в Vercel
5. **Save**

### Шаг 4. Сказать мне

Просто напиши в чат «Добавила `WB_CONTENT_TOKEN`» — и я подключаю код этой группы. Сам токен я не вижу, мне нужно только название.

## Что я сделаю когда токены появятся

Для каждого добавленного токена я:
1. Создаю миграцию таблицы (если нужно)
2. Пишу Edge Function-загрузчик с retry/rate-limit
3. Настраиваю cron в Supabase
4. Подключаю API в Next.js (server actions)
5. Заменяю моковые данные в UI на реальные
6. Добавляю проверку в `/health` — когда последний раз тянули

Один токен = один день работы максимум, обычно несколько часов.

## Меры безопасности

- Каждый токен в WB — на одну группу методов, не «все включить»
- Срок действия — год, потом переоформляем
- Если токен утёк (попал в чат, скрин, git) — сразу отозвать в WB-кабинете и создать новый
- В Vercel/Supabase env-переменные шифруются, в логи не попадают
- Никогда не пиши токены в код, в комменты, в commit
