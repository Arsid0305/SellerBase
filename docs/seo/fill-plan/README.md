# Пересборка карточек — метод и состояние по каталогу

> Замер 2026-08-27. Источники: `sku_catalog`, `wb_subject_charcs`, `v_sku_card_review`,
> `wb_keyword_clusters`, `wb_reviews_fact`.

> **Регламент цикла — [`../card-assembly.md`](../card-assembly.md)**: свод фактов → план →
> одобрение владелицы → действие. Здесь ниже — метод перебора полей и состояние по группам.

## Метод

Карточка перебирается **целиком, по полному списку полей предмета**, а не по списку пустых
полей. Заполненное значение не считается верным на том основании, что оно заполнено:
большинство внесено три года назад, под правила ранжирования, которых больше нет.

Каждое поле получает одно из шести решений:

| решение | что значит |
|---|---|
| **стоит верно** | проверено против канона и данных, не трогаем |
| **исправить** | значение есть, но неверное, устаревшее или не работает как фильтр |
| **заполнить** | пусто, значение известно |
| **замерить / уточнить** | пусто или спорно, нужен физический замер или поставщик |
| **ваши данные** | документы, налоги — знает только владелица |
| **не заполняем** | сознательное решение; в ревизии не висит задачей |

Порядок по весу полей — `../keyword-placement.md` §8: характеристики → наименование → описание.
Внутри группы порядок другой и он важнее: **сначала снимаются блокеры** (расхождения в
габаритах, склейка значений через запятую), потому что заливать текст поверх неверной
цифры — значит закрепить ошибку.

Один разбор группы = один файл в этой папке.

### Два правила, которые дались дорого

**Смотреть на товар, а не достраивать его по данным.** На массажёрах я вывел «блокер»:
в карточке длина 110 см, в упаковке 55, изделие жёсткое — значит одна цифра неверна.
Фотография показала гибкую ленту, которая складывается пополам. Обе цифры были верны,
блокера не было, а заодно рассыпались ещё два вывода, построенных на той же выдумке
о конструкции. **Перед разбором группы — фотографии товара.**

**Выгрузка частотностей замкнута на то, что в карточках уже написано.** `wb_keyword_clusters`
содержит кластеры, которые WB привязал к нашим номенклатурам, — то есть запросы, по которым
карточку уже показывали. Слова, которых мы ни разу не написали, в выгрузке отсутствуют
независимо от спроса: «ленточный» не встречается ни разу, хотя тип товара именно такой и
покупатели в отзывах сравнивают его с деревянным ленточным. Отсутствие кластера — **не**
доказательство отсутствия спроса. Проверять такие гипотезы можно только свежей выгрузкой
из кабинета после правки текстов.

### 3. Дублирующиеся описания — 24 SKU

Девять текстов повторяются побайтово. Крупнейший случай — восемь кап на одном описании
в 479 знаков.

### 4. Длина описаний: перекос в обе стороны

Ориентир канона — **1 500–2 000 знаков** (`../../SEO_MARKETPLACES.md`).

| предмет | средняя длина | что не так |
|---|---|---|
| Капы | 479 | втрое ниже нижней границы, 8 SKU |
| Эспандеры | 973 | ниже границы, 4 SKU |
| Бандажи косметические | 1 020 | ниже границы, 3 SKU |
| Шпатели кондитерские | 1 172 | ниже границы |
| Ножи для пиццы | 1 450 | на границе |
| **Массажеры механические** | **3 087** | в полтора раза выше верхней границы, 23 SKU |

Массажёры — обратная проблема: тексты не короткие, а перегруженные. Это сходится с замером
распределения ключей: описание тащит 119 ВЧ и 419 СЧ там, где канон отводит ему 3–5.

### 5. Цвет: 61 SKU с несколькими значениями, из них законно 10

Десять карточек — наборы разноцветных предметов (артикул на `CL`: таблетницы, эспандеры,
пробки), там пять значений описывают комплект и стоят по делу.

Остальные — один цвет, записанный синонимами: «белый · кремово-белый · молочный»,
«оранжевый · рыжий · яркий оранжевый», «нежный розовый · розовый · светло-розовый».
Приём прошлых лет: занять три ячейки фильтра вместо одной. Сегодня покупатель,
отфильтровавший «нежно-голубой», получает то, что мы сами зовём «голубой» — это возврат,
а нерелевантные теги с 01.05.2026 ещё и в списке оснований для теневого бана.

Разбирать надо по одной: часть случаев честные (двухцветная капа «бело-синий · белый · синий»),
и отличить их от синонимов можно только глядя на фото.

### 6. Склейка значений через запятую — 3 SKU

| поле | SKU |
|---|---|
| Действие | `ACRB1MS101BL`, `ACRB1MS101PN` |
| Комплектация | 1 SKU |

Узкое место, но срочное: с 01.05.2026 это основание для теневого бана до 30 дней.
Проверено по всему каталогу — больше нигде такого нет.

### 7. Мелочь, которая говорит о методе

В поле «Материал изделия» у шпателей стоит **«метал»** — опечатка. Значение-сирота: оно не
совпадёт ни с одним фильтром и не найдётся поиском. Ровно та причина, по которой заполненное
поле нельзя считать верным без проверки.

## Очерёдность групп

Считаю разумным идти так, и вот почему:

1. **Массажёры механические** (23 SKU) — самая большая группа, худший перекос по описаниям,
   единственная склейка значений, и по ней уже собрано ядро и разобраны отзывы.
2. **Мешки для стирки** (12) и **Таблетницы** (10) — следующие по объёму.
3. **Игрушки для животных** (7), **Скакалки** (4), **Эспандеры** (4) — средние группы.
4. **Бандажи косметические** (3) — маленькая, но с самым высоким негативом в отзывах (11.7%,
   в основном размер), то есть с самой быстрой отдачей от правки.
5. Одиночки: пробки, ножи, шпатели, консервный нож.

**Капы (8 SKU) — по решению владелицы не трогаем**, хотя по цифрам они худшие в каталоге:
35% заполненности, наименование в 15 знаков на восьми карточках, одно описание на всех.

## Что не покрыто этим методом

- **Фотографии и инфографика** — следующий этап после текстов. ИИ-модератор WB читает текст
  с инфографики наравне с описанием, поэтому пересборка текстов и картинок связана.
- **Справочники допустимых значений WB** по полям вроде «Действие» и «Зона массажа»:
  через API предмета площадка отдаёт только имена полей, не списки значений. Пока опираемся
  на значения, уже принятые в наших карточках.
