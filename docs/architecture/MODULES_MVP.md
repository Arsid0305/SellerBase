# Модули MVP — SellerBase Frontend

> **Статус:** план первого релиза. Шесть продуктовых модулей + фундамент.
> Порядок реализации обязателен (зависимости снизу вверх).

## Контекст и принцип отбора

MVP-набор отобран на основе разбора трёх референсов:

- **InSales Analytics** — бенчмарк ежедневной работы селлера (Сводка / Товарная аналитика / P&L / Оборачиваемость / Дефицит / Реклама / Источники / Поиск ниши)
- **MP Profit** — бенчмарк финансовой правды (P&L / ДДС / Юнит-экономика / Прогноз поставок / Команда)
- **SellerStats** — бенчмарк внешней аналитики рынка (Позиции запросов / SEO / Поиск ниши / Биддер ставок)

Критерий «в MVP»: фича присутствует минимум в 2 из 3 эталонов **И** опирается
на данные, которые уже подтянуты в Supabase **ИЛИ** требуют только новой VIEW
поверх существующих таблиц.

## Что уже есть в данных (Supabase)

- `sku_catalog` — товары, штрихкоды, себестоимость
- Заказы WB / Ozon (за период)
- Остатки WB (по складам)
- `get_full_pnl_by_period(...)` — функция расчёта P&L
- `v_supply_recommendation` — VIEW рекомендаций к поставке (дефицит)
- Ставки комиссий маркетплейсов
- Доп. расходы (планируется ручной ввод)

## Модули в порядке реализации

### M0 — Фундамент (1 неделя)

Не пользовательский модуль, но без него ни один следующий не делается.

- Bootstrap Next.js 15 + pnpm + TS strict + Tailwind + shadcn init
- FSD-структура папок (`app/`, `widgets/`, `features/`, `entities/`, `shared/`)
- ESLint flat + Prettier + Husky + lint-staged
- Vitest + Playwright базовая обвязка
- Supabase client + типы из БД + Auth (magic link + Google OAuth)
- AppShell: sidenav + topnav + theme toggle + PeriodComparePicker (заглушка)
- 7 доменных компонентов (см. `UI_STACK.md` раздел «Доменные компоненты»)
- Dockerfile (standalone) + `.github/workflows/ci.yml` (lint/type/test/build/docker)
- Sentry init, `env.example`

**Результат:** пустые страницы под все 10 разделов, рабочий каркас, CI зелёный, Vercel preview-URL.

---

### M1 — Сводка (Dashboard) — S

**Зачем:** одна страница, на которую заходят каждое утро.

**UI:**
- 4 `<KpiCard>`: Доходы / Основные расходы / Доп. расходы / Прибыль (с дельтой % к прошлому периоду + sparkline)
- Dual-line chart: доходы vs расходы по дням/неделям/месяцам
- Donut: доля каналов по продажам (WB / Ozon)
- `<PeriodComparePicker>` в шапке

**Данные:** `get_full_pnl_by_period()` — есть. ✅

**Зависит от:** M0.

---

### M2 — Прибыль и убытки (P&L) — M

**Зачем:** финансовая правда — главная боль селлера и сильнейшая фича MP Profit / InSales.

**UI:**
- Dual-line chart доходы vs расходы
- 4 KPI с дельтами
- Табличный P&L с группировкой по статьям (Комиссия МП / Логистика / Обработка / Эквайринг / Себестоимость / Продвижение / Штрафы / Другое / Доп. расходы)
- `<PeriodComparePicker>` со сравнением периодов
- Экспорт Excel

**Данные:** `get_full_pnl_by_period()` — есть. Доп. расходы — **новая таблица `expenses`** (ручной ввод).

**Зависит от:** M1.

---

### M3 — Дефицит товаров — S

**Зачем:** прямые потери денег, каждый день критичен. Простой и быстрый win.

**UI:**
- `<DataTablePro>`: товар + штрихкод + канал + склад + метки (PPP/A/Z) + упущено ₽ + прогноз ₽ + хватит на N дней + к поставке + продажи/день + остаток
- Цветовая семантика «Хватит на 0 д» красным (`<ProductTagBadge>`)
- Сортировка по упущенной выручке по умолчанию
- Экспорт Excel

**Данные:** `v_supply_recommendation` — есть. ✅

**Зависит от:** M0.

---

### M4 — Товарная аналитика + ABC×XYZ — L

**Зачем:** «убийственный» дифференциатор InSales — двумерная матрица товаров.

**UI:**
- `<AbcXyzMatrix>` 4×3 (PPP/PP/P/-P × A/B/C/X/Y/Z) — drill-down по клику в зону
- `<DataTablePro>` товаров с фильтрами, тегами, сортировкой
- KPI: «Товары без себестоимости» (счётчик)
- `<PeriodComparePicker>` + `<MarketplaceFilter>`
- Экспорт Excel

**Данные:** заказы + остатки → расчёт ABC (по выручке) и XYZ (по коэф. вариации продаж). **Новая VIEW `v_product_abc_xyz`** или edge-function.

**Зависит от:** M0, новая VIEW в БД.

---

### M5 — Оборачиваемость — M

**Зачем:** «деньги в товаре» — сколько застряло на складах.

**UI:**
- 4 сегмент-карточки: Все / Стабильная / Средняя / Нестабильная (с KPI: продажи шт./₽, остаток шт., избыточные, закончились)
- Динамика оборачиваемости по группам — line chart
- Drill-down таблица товаров сегмента

**Данные:** заказы + остатки + расчёт скорости. **Новая VIEW `v_turnover`.**

**Зависит от:** M4 (использует XYZ-классификацию).

---

### M6 — Отчёт по продажам — S

**Зачем:** базовый pivot для бухгалтерии и сверки.

**UI:**
- Pivot-таблица: периоды × каналы × товары
- Группировка переключается
- Экспорт Excel

**Данные:** заказы — есть. ✅

**Зависит от:** M0.

## НЕ в MVP (намеренно)

| Фича | Откуда | Почему не сейчас |
|---|---|---|
| Биддер ставок WB | SellerStats | Write-доступ к API WB, денежные риски, отдельный продукт |
| Авто-ответы на отзывы | SellerStats | NLP, отдельный data-pipeline |
| Позиции по запросам / SEO | SellerStats | Внешний скрапинг выдачи WB/Ozon — отдельная инфраструктура |
| Поиск ниши Ozon | SellerStats / InSales | Отдельный data-warehouse конкурентов |
| ДДС (cash flow) | MP Profit | Нужны банковские интеграции |
| Таск-менеджер / KPI сотрудников | MP Profit | Не profit-критично — релиз 2 |
| Браузерное расширение | SellerStats | Отдельный проект |
| Мобильное приложение | MP Profit / InSales | Web-app responsive хватит на старт |
| Я.Маркет / МегаМаркет / Детский Мир | все | Старт только WB + Ozon, остальные после PMF |
